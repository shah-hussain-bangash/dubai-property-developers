Step652 - Admin member suspension and reactivation

Open Admin > Account security (/security) > Member account access.
Select Suspend account or Reactivate account, enter a reason (5-300 characters),
confirm the current Admin password, and confirm the change. Installation changes
no member account. The owner cannot be suspended through this member-only control.

Suspension atomically records the state and invalidates every session for the
selected member. Login rechecks the state after password verification; existing
sessions and member security actions reject suspended accounts. Public sign-in
uses the existing generic invalid-credentials response. Reactivation never restores
old sessions: the member must sign in again. Stale/concurrent access changes are
rejected using a version. Reasons remain private to the Admin directory. A bounded
security history records actor, action, time and revoked-session count; the member
can see their account actions after reactivation. Only the latest reason is retained.

Properties, photos, clients, enquiries and agent approval remain intact. Suspension
blocks account authentication; it is not a withdrawal of already public property
listings. Use Website listing review separately to withdraw published listings.
Requests authorized before suspension may finish; this release does not introduce
a cross-store transaction spanning every business operation.

Existing member records default to active, with access version zero. Encrypted
portal snapshots retain and validate the new state. Corrupt state fails closed.
Backups from older dates retain their historical access state: a future full restore
must reconcile later suspensions. This remains a local deployment with existing
storage/retention limits. Email verification, email password recovery, MFA/passkeys,
invitations, company isolation and production API identity remain later milestones.

Installer preserves owner credentials and Meta settings and refreshes the dashboard
only. API, PostgreSQL, Redis, n8n, research runner and 33 review holds are preserved.
No provider connection, credential prompt, real suspension or message is performed.
