STEP 639 — DUBAI PROPERTY DEVELOPERS LOCAL WEBSITE AND MEMBERS

Design
The supplied Home Page reference drives the white navigation, navy/amber palette,
large Dubai waterfront hero, four property paths, six collaboration features,
community cards and filters, workflow, FAQ, call to action and dark footer.
All content is written for Dubai Property Developers. The Current Opportunities
page uses the same brand and provides honest community exploration without
inventing live inventory, prices, commissions, developer partnerships or returns.
Sign-in and sign-up share the brand, property imagery and responsive styling.

Identity boundaries
The existing Step638 owner email, scrypt password hash, sessions and named volume
are reused. The API and research runner are not restarted. No SerpApi key or
owner password is requested. The launcher reads only three named portal settings
from the dashboard process in memory, never a full container environment.
No plaintext password is written into a script, host file or Docker arguments.

New registrations create actual local member accounts and an eight-hour session.
Members have /account with their name, company, selected role and property interest.
The selected role is descriptive only and grants no administrative privilege.
Members cannot access /overview, /prospect-research or the owner API gateway.
Only the pre-existing owner identity opens the operations workspace.
Email verification, password recovery, live offers and enquiry delivery are not
connected. Those limits are displayed in the relevant user flows. No marketing
permission is inferred from signup. Accounts currently support local use only;
the existing direct development API remains a trusted localhost endpoint.

Member storage
members.json and members.lock use the existing /app/portal-data named volume.
File locking, atomic replacement and sync protect concurrent updates. Passwords
use unique random salts with scrypt N32768/r8/p3, 64-byte keys and 64MiB max memory.
Only session digests are stored. Owner and member cookie names and session stores
are separate. HttpOnly, SameSite Strict, host-only cookies expire after eight hours.
Same-local-origin checks guard signup, login and logout. JSON requests are bounded
to 4096 bytes and allowed fields; signup cannot supply owner/admin privileges.
Ten signup attempts or ten member login attempts per fifteen minutes are allowed.
There are bounds of 200 member accounts and 2000 active session records for this
local edition. Session expiry and sign-out are enforced server-side.
The volume contains personal profile details and salted hashes; include it in
your private local backup policy. The existing prospect JSON export does not
export member accounts. No deletion/reset UI or external mail delivery is added.

read/network permission. The supplied logo attachment was faithfully rendered

It is an attachment-derived rendering, not a byte-identical copy of the shared file.
The original attachment remains unchanged. The prepared site asset is:

2. villa.webp: premium architectural photograph of a contemporary Dubai villa,

The project copies are high-quality WebP files. Original generated PNGs remain
in the tool's generated_images folder. Site assets are bundled, not hotlinked.
Cards label AI-created imagery as community inspiration, not live listings.

Verification
526 frontend tests, including 15 member security/storage/route cases and five
website interaction cases. Strict TypeScript. Six offline refresh simulations.
Actual HTTP preview checks cover owner login/logout, member signup/login/logout,
member/owner isolation and cross-site registration rejection using fictional
profiles in an isolated local preview store. No real account, prospect, reply,
search, message or call is created by the installer/refresh acceptance checks.
Browser visual QA covers homepage, property cards, sign-in and sign-up at the
available desktop viewport. Responsive breakpoints are implemented; a mobile
viewport screenshot was not available through the attached browser controls.
