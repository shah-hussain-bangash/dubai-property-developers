# Review dates for every knowledge import

Verified locally on 26 November 2026 against parent
`8a0ba430d17da4d205d4361ec7db308a92542049` plus this change in
[PR 87](https://github.com/shah-hussain-bangash/dubai-property-developers/pull/87).
The commit containing this record identifies the implementation. All material is
fictional; no live CRM, email, messaging or website import was used in the browser.

## Gap and change

The source store and JSON import API already supported review deadlines, but the
Knowledge page could not set or display them. Raw PDF, text and Markdown uploads
could not set a deadline either. Staff now have an optional Review by date for
all import methods. File uploads send it as a `review_by=YYYY-MM-DD` parameter;
pasted text and website snapshots use the existing JSON field. File date parsing
rejects invalid, non-calendar and noncanonical formats. The existing store rejects
dates before its current day. Blank or absent dates remain compatible.

Each saved source displays its stored review deadline, or No review deadline.
Changing the draft date clears customer approval, just like other source edits.
Successful saves and agent switches clear the draft date. Failed saves retain it.
There is no browser-derived expired/fresh badge: the backend is authoritative.

Existing behavior remains: a dated source is eligible through its review day and
excluded afterward according to the server calendar day. Identical re-imports
without a date preserve their existing deadline, including an expired one. An
explicit current/future review date can renew reviewed material. Renewal does not
prove that its facts are correct; staff must review the material and grant any
customer approval explicitly. Undated sources have no automatic date cutoff.
No source schema, retrieval threshold, agent permission or queued-send policy changed.

## Browser acceptance

The local API used mock providers and a disposable source database. Its source
calendar was controlled by a fixture, initially `2030-01-02`, then `2030-01-03`.
The machine clock and production settings were not changed. These future dates
are simulated test days, not dates when the browser session actually happened.
The browser used the local development identity; authenticated organization/role
boundaries are covered by API regression tests.

1. Sign in to the local admin workspace, open Knowledge and select Document Agent.
2. Upload the two-page fictional PDF generated by
   `tests.security.test_agent_source_format_journey.pdf_fixture("datemarker")`.
   Title it Fictional review PDF and set Review by to `2030-01-02`.
   Leave customer approval unchecked. Confirm the saved list shows that deadline.
3. Ask `datemarker pdfmarker`. The page quotes
   `Fictional datemarker pdfmarker policy allows three visits.` with Page 2.
   [Valid on review day](assets/source-review-dates-2026-11-26/01-reviewed-pdf.jpg).
4. Advance only the disposable source clock to `2030-01-03`. Ask again: the
   explicit no-answer response replaces the excerpt. Re-upload the identical PDF
   with Review by blank, then ask again. The deadline stays `2030-01-02`, one
   saved source remains, and the answer stays unavailable.
   [Expired deadline preserved](assets/source-review-dates-2026-11-26/02-expired-preserved.jpg).
5. Re-import that PDF with an explicitly reviewed new deadline `2030-01-04`.
   Ask again: the same Page 2 excerpt returns, one source remains, and its saved
   date is `2030-01-04`.
   [Renewed source](assets/source-review-dates-2026-11-26/03-renewed-pdf.jpg).
6. Sign out, stop the disposable servers and remove the temporary login material.

The browser automation's initial date fill did not emit a change event; native
keyboard edits committed the date correctly. The accepted sequence above used
committed dates, verified both in the saved source list and final database record.
No product workaround or change to date events was made for the automation tool.

[Structured evidence](source-review-dates-local-2026-11-26.json) records the source
content ID and observed outcomes. The test-clock launcher, login material and
private database are outside the published repository.
