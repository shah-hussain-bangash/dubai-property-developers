Step653 - Member email verification and password recovery

Admin: /security shows Security email delivery and the last provider attempt.
Member: /account/security shows email ownership and a verification-link request.
Public: /forgot-password requests member reset email; /reset-password and
/verify-email consume the fragment link only after an explicit button action.
Admin/owner password recovery remains private local setup, not email recovery.

DELIVERY SETUP - NOT ACTIVATED BY INSTALLATION
The requested sender is owner@example.com. Privately authorize that
mailbox for the Gmail API gmail.send scope using your Google OAuth application.
Enable the Gmail API and obtain your own OAuth Client ID, Client Secret and
offline refresh token. This release does not implement Google browser OAuth
enrollment. Run step653_connect_email.ps1 once those credentials are ready.
Never enter your Gmail password, App Secret, refresh token or reset link in chat.
The connector validates entries and recreates only the dashboard. It does not
send a test email or connect the mailbox inbox. The next explicit member link
request uses the authorized sender. Verify one real message in a controlled test.
Settings stay in the container environment; Docker administrators can inspect them.
No host credential file or secret command-line argument is written. No delivery
is claimed by a configured indicator; the provider receipt is not proof of inbox
delivery. No credentials are supplied in this delivery package.

Default link origin is http://localhost:3000. Such links work only on the machine
running the site. A controlled HTTPS site origin must be configured for remote
members. Link origin comes from private configuration, never the request Host.
This does not deploy the website or change existing localhost-only origin checks.

SECURITY CONTRACT
32-byte random tokens are stored only as SHA-256 digests. Verification expires
after 24 hours, reset after 15 minutes. Purpose and current credential/access
version are bound to each link. Failed/unconfirmed sends invalidate the link;
only a receipt from Gmail activates it. No send is automatically retried.
Issuing a replacement invalidates the previous link of the same purpose. A
password change/reset or suspension/reactivation invalidates relevant links.
Suspended accounts cannot recover themselves, and the owner is excluded.
Reset consumes under the member lock after hashing, revokes all member sessions,
verifies email ownership and requires fresh sign-in. Concurrent/reset replays fail.
An explicit verification also records ownership; it does not approve agent access.
Existing registrations and approval rules are preserved: verification is an
ownership marker in this stage, not a new mandatory gate on all legacy accounts.

Public reset requests return the same message for unknown, owner, suspended and
eligible members, with a minimum 9-second response interval for configured valid
requests. Fixed provider calls are bounded to 3.5 seconds each and not retried.
No token, raw password or provider error is returned. Same-origin checks and
bounded JSON apply. Limits: 20 request attempts per 15 minutes globally, 3 per
email with a 60-second cooldown, and 30 link consumption attempts per 15 minutes.
These are local service limits; multi-instance/distributed controls are future work.

Tokens use URL fragments and are removed from the address bar on page load.
GET does not consume tokens. Link pages have no-referrer/no-store headers and
no automatic redirect to a supplied URL. Emails and browser memory contain the
link secret; share neither. Active links/attempts are excluded from encrypted
backups and rejected on archive validation. Verification status and security
events remain. Restoring historical account state needs a controlled procedure;
do not roll back to older identity code that ignores newer security fields.

Security history is bounded and still not a complete tamper-evident audit system.
MFA/passkeys, invitations, owner recovery redesign, production identity protection,
mailbox OAuth enrollment, mail delivery monitoring and public hosting remain later
milestones. Other social, campaign and research flows remain unchanged.
