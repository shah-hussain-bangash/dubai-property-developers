environment. On this Windows setup Docker Compose fails with the original environment
and its plugin/config validation succeeds when PROGRAMFILES is retained. APPDATA alone
is not sufficient. Keep filtering
provider keys and Docker remote-host overrides; preserve APPDATA, PROGRAMFILES and PROGRAMFILES(X86) for Docker Desktop.
This repair changes only scripts/local_n8n.py and its offline tests, plus this note.
It does not change Compose settings, the pinned image version, data volumes, accounts,
workflows, the property API/dashboard/researcher or any of33 review holds.

Run step649_fix_apply.ps1. It checks installed Step649 evidence, backs up changed
sources, runs32 offline checks, installs separate repair evidence, then retries n8n
startup using the repaired launcher. No account/password/API key entry is requested.
Use step649_fix_start.ps1 for future n8n verification/start attempts after this repair;
the original Step649 launchers remain sealed against the older source revision.
Existing stopped/orphaned instances still require deliberate review before resuming.

Compose discovery/config, image download/digest and container/volume checks. Raw Docker
stdout/stderr, settings and secrets are never printed. An engine permission error may
