LOCAL RESEARCH JOB RUNNER - STEP 634

This adds an optional foreground Windows runner for one existing saved research
job. It does not change the dashboard, API, database schema or search settings.
Installation runs only offline tests. It never starts a research job.

After installing, run outputs/step634_start.ps1 from the delivery directory.
The launcher lists saved job IDs, statuses and source-candidate counts. Enter the
number for the job you want to run, or press Enter to cancel. Selecting a job
starts automatic query advancement using the existing provider allowance.

Keep the terminal open, Docker/API running, and the computer awake. At quota_wait,
the runner checks saved state at most once per minute and waits until the stored
Dubai quota reset. It then advances one query. A successful provider attempt adds
an additional in-process wait until the next Dubai midnight. Before each advance,
the connection must still be enabled SerpApi with daily limit exactly 1. It cannot
raise or bypass the server's shared Redis quota. Manual discovery shares it.

Only one selected job runs. A Windows global named mutex prevents duplicate local
runners for that job, including across login sessions. The API's existing tenant,
revision and PostgreSQL advisory-lock guards still serialize actual advances.
Each run stops after at most 60 provider attempts by default, or sooner when the
saved plan finishes. --max-attempts permits a bounded value from 1 through 100.
These are source candidates, not verified people, contacts or buying ability.

Ctrl+C stops the runner. Pause or Cancel in the dashboard is observed within
60 seconds while waiting. A provider request already in flight may finish before
stopping. The runner never automatically resumes paused/cancelled jobs or skips
an uncertain query. HTTP failures, conflicts, unexpected state, provider errors
and request_uncertain stop without an automatic retry. Reload the saved job in
the dashboard before restarting after any uncertain outcome.

No Windows scheduled task, background service, login startup or Codex automation
is created. Closing the terminal, shutting down or restarting the computer stops
the runner. Sleep suspends it; on waking it reloads saved state before acting.
An API outage stops it. Restarting requires running the launcher again. Nothing
is lost from the saved PostgreSQL job by stopping this process.

All HTTP requests go only to fixed 127.0.0.1:8000 research endpoints. Proxies and
redirects are disabled. The runner never receives or stores a provider key and
does not print source contents, contact details or raw API errors. No key entry,
Docker rebuild, service restart or database provisioning is needed.

The dashboard still correctly says its own unattended scheduling is not enabled:
the separate terminal process performs automatic advancement while open. Use
Reload selected job to see its latest progress. The runner does not modify saved
prospects, infer contact fields, generate PDFs, send email/WhatsApp, notify owners
or place calls. Existing prospect PDF exports remain available separately.

Direct use: python -I -B scripts/run_prospect_research_job.py --job-id JOB-ID
Read-only list: python -I -B scripts/run_prospect_research_job.py --list
