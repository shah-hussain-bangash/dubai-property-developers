Step 643 - Client Desk and viewing/follow-up planner

Requires Step642 installed and serving. Install with step643_apply.ps1.
Dashboard-only refresh preserves accounts, properties, private photos, API and research runner.
No provider searches, external messages, calls or notifications are performed.

Agent Portal navigation:
Client Desk: create/edit private client records and stated property requirements; optional contact details.
Stages: New, Qualified, Viewing, Offer, Won, Lost. Stages are manually recorded, not inferred.
Search and stage filters work on current records; archived records have a separate filter.
Property matches: only Available, non-Trash listings from the signed-in agent's portfolio.
All criteria must match: Sale/Rent purpose, inclusive budget range, minimum bedrooms, type
(or Any), and case-insensitive community keyword (blank means any). Up to 30 cheapest matches
are shown. Budget for rentals is annual. Matching does not establish buying ability or permission.
Shortlist: up to four owned current properties per client; live comparison of price, location,
beds, area and current fit. A previously shortlisted listing may change status or move to Trash.
Clear shortlist removes all stored selections. Changes require the current client version.

Viewings & follow-ups: save local tasks with links to owned clients/properties, notes and status.
Viewing requires a property. Times are entered/displayed in Dubai GST (UTC+4), regardless of
the device timezone. End must be after start and within 24 hours. Past records are allowed.
Planned viewings cannot overlap any other planned viewing for the same agent. Adjacent slots
are allowed. Follow-up tasks do not reserve a viewing slot. Completed/Cancelled records remain.
Mark completed, edit/reschedule/cancel/reopen, type/status/date/search filters, overdue and next
7-day counts are connected to actual records. Local display counts refresh each minute.
Download calendar exports a UTC ICS file for manual calendar import. It does not send invitations,
sync calendars, schedule system notifications or contact the client.
Archiving a client cancels all linked Planned tasks in the same locked write. Completed history
and the shortlist stay. Restore does not reopen cancelled tasks. Archive confirmation explains this.
Property Trash does not cancel an existing appointment; the planner flags the unavailable link.

Overview includes actual active-client counts and the next planned tasks. Workflow events appear
in the existing agent-scoped activity timeline. Owner/Admin operations access remains separate.
Client and task APIs require an approved agent; reads and writes are scoped to that agent.
All mutations use the existing lock, bounded JSON input, origin checks and optimistic versions.
Existing schema-1 records load without new fields. Optional clients/tasks arrays are added in
agent-portal.json under the same private portal-data volume. Limits: 500 clients, 1000 tasks
across this local workspace; existing shared audit retains at most 1000 events.
Back up the entire existing portal-data volume, including property-photos.
This remains the established local development setup; it is not an internet deployment.
